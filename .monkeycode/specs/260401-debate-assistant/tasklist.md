# 需求实施计划

- [ ] 1. 搭建桌面端项目骨架与共享核心模块
  - 创建基于 `Tauri + React + TypeScript` 的目录结构，划分 `apps/desktop`、`packages/core`、`packages/integrations`、`packages/workflows`，对应设计中的桌面壳、共享核心服务与适配层，覆盖 Requirement 11.1、11.2 与设计文档 Architecture。
  - 定义事件总线、模块注册、配置加载与依赖注入边界，为 `audio-capture`、`asr-orchestrator`、`argument-parser`、`fallacy-engine`、`seat-strategy-engine`、`tactic-card-generator`、`timeline-engine`、`knowledge-base` 提供统一接口，覆盖 Requirement 8.1、10.3 与设计文档 Components and Interfaces。
  - 集成基础代码规范、类型检查、构建脚本与桌面端开发命令，为后续自动提交脚本与 CI 铺路，覆盖 Requirement 12.1、12.2、11.1。
  - [ ] 1.1 为模块注册和事件总线编写单元测试与属性测试
    - 验证事件顺序不乱序、模块初始化依赖满足、重复注册被拒绝，对应设计文档 Correctness Properties 4。

- [ ] 2. 实现核心数据模型、会话配置与赛制模板校验
  - [ ] 2.1 创建比赛会话与策略配置模型
    - 实现 `DebateSession`、`StrategyProfile`、`RoundState`、`RuleTemplate`、`SeatGoal` 等类型与校验器，覆盖 Requirement 1.1、1.2、1.3、10.1、10.4 与设计文档 Data Models。
    - 支持辩题、立场、席位、语言、核心论点、禁忌表达、输出风格、极简模式等字段。
  - [ ] 2.2 实现“新国辩类”默认模板与模板编辑能力
    - 编码默认回合顺序、允许席位、时长、回合提示点与席位目标权重，同时预留自定义模板增删改查接口，覆盖 Requirement 1.4、5.1、10.1、10.2、10.3。
  - [ ] 2.3 实现模板完整性校验与开赛前阻断逻辑
    - 在模板字段缺失、席位映射错误、回合时长非法时阻止比赛启动，覆盖 Requirement 10.4 与设计文档 Correctness Properties 4。
  - [ ] 2.4 为模板校验与会话模型编写单元测试和属性测试
    - 验证任意合法模板都能生成可遍历时间线，非法模板都会返回明确错误，对应设计文档 Correctness Properties 4。

- [ ] 3. 实现赛前配置界面、资料导入与知识库索引
  - [ ] 3.1 构建比赛创建与配置向导
    - 实现辩题、立场、席位、语言、模板选择、论点树录入、禁忌表达配置与首次启动权限引导界面，覆盖 Requirement 1.1、1.2、1.3、11.4。
  - [ ] 3.2 实现资料导入、冲突检测与可检索知识库存储
    - 支持导入资料卡、案例、数据、稿件并建立标签和关键词索引；对冲突结论标注来源，覆盖 Requirement 7.1、7.2、7.3、7.4。
  - [ ] 3.3 实现赛前上下文持久化与本地存储策略
    - 保存比赛配置、资料库索引、最近使用模板与本地隐私选项，覆盖 Requirement 1.2、9.1、11.3 与非功能需求 3。
  - [ ] 3.4 为知识库检索与冲突检测编写单元测试
    - 验证关键词检索命中、冲突来源可回溯、脱敏存储策略生效。

- [ ] 4. 检查点 - 确保所有测试通过
  - 确保当前项目骨架、会话模型、赛制模板与赛前配置相关测试通过，并验证桌面端可以启动基础空界面。

- [ ] 5. 实现音频采集、实时转录编排与降级识别通道
  - [ ] 5.1 实现桌面端音频输入与设备管理
    - 编写 `audio-capture` 模块，支持麦克风输入、设备切换、权限状态展示和统一 PCM 输出，覆盖 Requirement 2.1、2.2、11.3、11.4 与设计文档 Error Handling。
  - [ ] 5.2 实现实时转录编排器与增量文本流
    - 编写 `asr-orchestrator`，支持切片、时间戳、稳定度、置信度、异常重试与备用识别策略切换，覆盖 Requirement 2.1、2.2、2.3、2.4、8.1、8.2、9.2。
  - [ ] 5.3 实现离线缓存与半自动输入降级模式
    - 当 ASR 或网络不可用时保留转录时间线，允许人工补录关键句，覆盖 Requirement 2.4、9.1、9.2、9.3、9.4 与设计文档 Correctness Properties 5。
  - [ ] 5.4 为转录切片、稳定文本合并和离线缓存编写单元测试与属性测试
    - 验证时间戳单调递增、增量文本不会倒退、网络中断不会丢失已确认片段，对应设计文档 Correctness Properties 5。

- [ ] 6. 实现论证解析、逻辑漏洞识别与可解释引用链
  - [ ] 6.1 实现转录片段到论证结构的解析器
    - 编写 `argument-parser`，抽取主张、论据、定义、比较标准、价值判断与立场冲突关系，覆盖 Requirement 3.1 与设计文档 Data Models `ArgumentFrame`。
  - [ ] 6.2 实现规则引擎级逻辑漏洞检测
    - 优先落地偷换概念、因果倒置、证据不足、标准漂移、双重标准、未比较、循环论证等规则检测，覆盖 Requirement 3.2、3.3、8.4、9.2。
  - [ ] 6.3 接入 LLM 深度分析并合并置信度
    - 让模型补充复杂漏洞判断、攻击方向与风险说明，对不确定结论标记“待核验”，覆盖 Requirement 3.2、3.4、8.1、8.3、8.4。
  - [ ] 6.4 实现证据片段引用与解释性元数据
    - 每个漏洞分析都关联原始转录片段与知识库引用，覆盖 Requirement 3.2、6.1 与非功能需求 2，对应设计文档 Correctness Properties 1、2。
  - [ ] 6.5 为漏洞检测规则与引用链编写单元测试和属性测试
    - 验证每条漏洞结果都至少关联一个来源、低置信度项不会被标记为确定结论，对应设计文档 Correctness Properties 1、2。

- [ ] 7. 实现席位策略引擎、回合时间轴与战术卡生成
  - [ ] 7.1 实现时间轴引擎与回合切换状态机
    - 根据赛制模板推进回合、剩余时间和提示节点，覆盖 Requirement 5.1、5.2、10.3 与设计文档 `timeline-engine`。
  - [ ] 7.2 实现一辩到四辩的席位策略引擎
    - 按席位与当前回合生成不同目标、排序权重、输出长度和语气，覆盖 Requirement 4.1、4.2、4.3、4.4、4.5 与设计文档 Rule Template Strategy。
  - [ ] 7.3 实现战术卡生成器与优先级排序
    - 输出“攻击点”“一句话反击”“可追问问题”“风险提示”等组合卡片，支持极简模式和前三优先级展示，覆盖 Requirement 6.1、6.2、6.3、6.4。
  - [ ] 7.4 实现时间敏感提醒与总结阶段聚合
    - 在回合末提醒收标准、打一条最强进攻、准备回扣评判；在结辩阶段汇总有效交锋点与未回应点，覆盖 Requirement 5.2、5.3、5.4。
  - [ ] 7.5 为席位策略和战术卡排序编写单元测试与属性测试
    - 验证自由辩末段不会生成长篇立论，所有卡片都符合当前席位和回合，对应设计文档 Correctness Properties 3。

- [ ] 8. 检查点 - 确保所有测试通过
  - 确保实时转录、论证解析、漏洞识别、时间轴和席位策略的核心流程在本地样例数据上可联通。

- [ ] 9. 实现实时辅助界面、降级反馈与复盘时间线
  - [ ] 9.1 构建比赛主界面与实时辅助视图
    - 展示转录流、当前回合、剩余时间、战术卡列表、知识库命中和风险标记，覆盖 Requirement 5.1、6.1、6.3。
  - [ ] 9.2 实现降级状态、置信度与不可用能力提示
    - 在 ASR/LLM/网络异常时明确显示服务状态、可信度和可用替代方案，覆盖 Requirement 2.4、8.4、9.2、9.3。
  - [ ] 9.3 实现复盘时间线与离线合并视图
    - 将转录、漏洞结果、战术卡和回合事件串联成可回放时间线，覆盖 Requirement 9.1、9.4 与设计文档事件存储与复盘索引。
  - [ ] 9.4 为主界面状态切换和复盘时间线编写集成测试
    - 验证回合切换、服务降级、离线恢复后的界面一致性。

- [ ] 10. 实现模型供应商适配、配置面板与安全边界
  - [ ] 10.1 实现 ASR 与 LLM 供应商适配层
    - 提供统一调用协议、超时控制、令牌消耗统计与失败原因记录，覆盖 Requirement 8.1、8.3、8.4。
  - [ ] 10.2 实现本地模型/私有化服务切换配置
    - 在设置中允许切换云端与本地推理路径，覆盖 Requirement 8.2、11.4。
  - [ ] 10.3 实现敏感信息隔离与日志脱敏
    - 避免 API Key、凭证文件和用户私密资料进入提交与日志，覆盖 Requirement 12.4 与非功能需求 3。
  - [ ] 10.4 为供应商适配层编写合约测试
    - 验证超时、重试、错误码转换和日志脱敏逻辑。

- [ ] 11. 实现自动提交工作流、CI 打包与多端发布管线
  - [ ] 11.1 实现本地开发自动提交脚本
    - 提供标准脚本串联 `git add`、描述性提交、`git push`、失败提示与敏感文件过滤，覆盖 Requirement 12.1、12.2、12.3、12.4 与设计文档 Packaging and Delivery。
  - [ ] 11.2 实现 GitHub Actions 多平台构建流水线
    - 构建 macOS 与 Windows 客户端包，执行静态检查、单元测试、关键回放测试与桌面打包，覆盖 Requirement 11.1、11.2、12.1。
  - [ ] 11.3 实现桌面端发布配置与平台差异适配
    - 处理麦克风权限、系统存储路径、安装包元数据与首次启动引导，覆盖 Requirement 11.3、11.4。
  - [ ] 11.4 为自动提交脚本和构建流水线编写集成测试
    - 验证推送失败时保留本地提交、CI 产物命名一致、平台构建参数正确。

- [ ] 12. 检查点 - 确保所有测试通过
  - 确保桌面端主流程、自动提交工作流和多平台构建配置均通过校验，并确认可以进入正式开发迭代。
